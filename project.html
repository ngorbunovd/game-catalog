1. Описание проекта

«Антология игр» — образовательный веб-проект для учебного заведения. Ученики разрабатывают самостоятельные HTML/CSS/JS-игры, подают их через кнопку на главной странице, преподаватель проверяет и подтверждает публикацию, а посетители каталога могут играть и ставить лайки понравившимся играм.

Ключевая идея — максимальная простота: никакой CI/CD, никакого Git-workflow для ученика, никакой сборки. Игра — это папка game-catalog/games/<slug>/ с четырьмя файлами, которую можно открыть двойным кликом по index.html и сразу играть. Каталог — это статическая страница, которая запрашивает список игр у минимального бэкенда и рендерит карточки с кнопками «Играть» и «Лайк».

Учебные цели

  • Практика HTML/CSS/JS на реальном проекте с обратной связью от сверстников.
  • Понимание структуры веб-проекта: клиент, сервер, API, статические файлы.
  • Навык оформления результата: обложка, описание, метаданные.
  • Знакомство с жизненным циклом публикации: разработка → подача → ревью → публикация.

Организационная модель

  • Ученик — автор игры; разрабатывает локально, отправляет ZIP через кнопку «Подать игру».
  • Преподаватель — модератор; проверяет заявку в админке, approve'ит или отклоняет.
  • Посетитель — ученики и сотрудники; играют и ставят лайки (по одному на игру).
  • Система — минимальный бэкенд для приёма заявок, хранения лайков и выдачи каталога.

2. Итоговый результат

По завершении проекта должны быть получены:

  • Главная страница «Антология игр» по адресу https://antology.local/ (файл game-catalog/index.html): список загруженных игр с русскими названиями из метаданных, обложками, описаниями, счётчиком лайков и кнопкой «Подать игру».
  • Папка game-catalog/games/ с папками игр. Каждая игра — это games/<slug>/index.html, style.css, script.js, game.json и cover.png. Открывается и тестируется напрямую, без участия каталога.
  • Механизм голосования: одна сессия пользователя = один лайк на игру. Лайк ставится и снимается. Счётчик отображается рядом с каждой игрой на главной странице.
  • Механизм подачи и одобрения:
    • Кнопка «Подать игру» на главной странице открывает форму: название, автор, описание, ZIP с папкой игры.
    • Заявка сохраняется на сервере в _pending/ и попадает в админку преподавателя.
    • Преподаватель одобряет заявку → папка переезжает в games/<slug>/ и игра появляется на главной.
  • Минимальный бэкенд (Node.js + Express) — API для списка игр, лайков, приёма заявок и админки преподавателя. Без БД, всё состояние — в JSON-файле и папках на диске.
  • Документация:
    • README.md — обзор, быстрый старт, структура, документация по ссылкам;
    • gamegenerateprompt.md — промпт-инструкция для генерации папки с игрой;
    • docs/CONTRIBUTING.md — как сделать и подать игру;
    • docs/TEACHER_GUIDE.md — как модерировать заявки;
    • docs/SECURITY.md — ограничения и защита.

4. План реализации

4.1. Архитектура (резюме)

[Ученик] --разработка в games/<slug>/--> [локальная проверка: открыть index.html] │ ▼ [Ученик] --ZIP через "Подать игру"--> POST /api/upload --> _pending/<id>/ │ ▼ [Преподаватель] --/admin--> approve/reject --> games/<slug>/ (публикация) │ ▼ [Гость] --GET /--> каталог (index.html) --GET /api/games--> список игр + счётчики [Гость] --клик по карточке--> games/<slug>/index.html (запуск игры) [Гость] --кнопка "Лайк"--> POST /api/games/<slug>/like (переключение лайка)

Ключевые принципы:

  • Один origin, один сервер. Nginx отдаёт статику (index.html, games/, admin/) и проксирует /api/* в Node.js.
  • Игры самостоятельны. Открытие games/<slug>/index.html работает без бэкенда и каталога — это и есть тестирование автором.
  • Без БД. 40 игр и 30 пользователей — это единицы килобайт JSON. Хватит одного файла data/votes.json и папки _pending/.
  • Без CI/CD. Нет пайплайна, нет сборки, нет preview-окружений. Код сервера ставится один раз, контент (игры) добавляется через админку.

4.4. Формат игры и схема метаданных

Каждая игра — это папка games/<slug>/ с обязательными файлами:

  • index.html — точка входа, при открытии игра запускается;
  • style.css — стили (может быть пустым);
  • script.js — логика (может быть пустым);
  • game.json — метаданные;
  • cover.png — обложка 512×512 или 512×256.

Дополнительно можно положить папку assets/ для картинок, звуков и шрифтов.

game.json — схема

{
  "$schema": "https://antology.local/schemas/game.schema.json",
  "slug": "snake",
  "title": "Змейка",
  "summary": "Классическая аркада: собирай яблоки и не врезайся в себя",
  "description": "Полное описание игры в markdown. Что за игра, откуда идея, чем интересна.",
  "author": {
    "name": "Иванов Иван",
    "class": "7А"
  },
  "genre": "arcade",
  "tags": ["змейка", "аркада", "классика"],
  "controls": "Стрелки или WASD",
  "ageRating": "0+",
  "coverImage": "cover.png",
  "language": "ru",
  "createdAt": "2025-11-16",
  "license": "CC-BY-4.0"
}

Обязательные поля: slug, title, summary, description, author.name, author.class, coverImage, createdAt.

Опциональные: genre, tags, controls, ageRating, language, license.

genre — из списка: arcade, puzzle, strategy, action, adventure, quiz, other.
ageRating — из списка: 0+, 6+, 12+, 16+, 18+.

slug должен совпадать с именем папки, соответствовать ^[a-z0-9][a-z0-9-]{1,40}$ и быть уникальным.

4.5. Главная страница каталога

Файл game-catalog/index.html — точка входа всего проекта. Содержит:

  • Заголовок «Антология игр» и краткое описание проекта.
  • Кнопку «Подать игру» — открывает модальное окно подачи.
  • Сетку карточек игр — рендерится JS из ответа GET /api/games.
  • Поле поиска и фильтр по жанру — фильтрация на клиенте.

Карточка игры

<article class="game-card">
  <img class="cover" src="games/snake/cover.png" alt="Обложка">
  <h3 class="title">Змейка</h3>
  <p class="summary">Классическая аркада...</p>
  <div class="footer">
    <button class="like">❤ <span class="likes">0</span></button>
    <a class="play" href="games/snake/index.html">Играть</a>
  </div>
</article>

Клик по карточке (или по кнопке «Играть») — переход на games/<slug>/index.html. Игра открывается на весь экран в новой вкладке или в iframe на странице-обёртке — оба варианта допустимы, предпочтителен iframe для сохранения контекста каталога.

4.6. Механизм голосования

Требование: один лайк на игру от пользователя; можно ставить и снимать; счётчик рядом с игрой.

Идентификация пользователя

  • При первом запросе к API сервер выдаёт session_id — случайный UUID, подписанный HMAC, в cookie antology_session (HttpOnly, SameSite=Lax, Secure).
  • Пользователь не регистрируется, аутентификации нет — сессия просто анонимный идентификатор.
  • Альтернативные меры (по IP) не применяются — это создаёт проблемы у учеников за общим школьным NAT.

Хранение

Файл data/votes.json:

{
  "snake": ["a1b2c3d4-...", "e5f6...", "..."],
  "tetris": ["a1b2c3d4-..."]
}

Размер файла — сотни байт на игру. При каждом лайке файл перезаписывается атомарно (запись во временный + rename).

API

МетодEndpointОписание
GET/api/gamesСписок игр: [{ slug, title, summary, author, coverImage, likes, liked }]. liked рассчитан для текущей сессии.
POST/api/games/:slug/likeТоггл лайка: если сессия уже в списке — удалить, иначе добавить. Возвращает { likes, liked }.

Ограничения и защита

  • Счётчик — это длина массива сессий; отдельного поля «количество» нет, чтобы данные не рассинхронизировались.
  • Очистка cookie даёт возможность проголосовать повторно — считаем это допустимым для учебного проекта (не деньги и не рейтинг с призами).
  • Rate limit: не более 20 запросов лайков в минуту с одной сессии (in-memory счётчик).
  • При переключении лайка фронт оптимистично обновляет счётчик и откатывает, если сервер вернул ошибку.

4.7. Подача игры и модерация

Фронтенд: форма «Подать игру»

Модалка на index.html содержит:

  • Название игры (обязательное, используется как основа slug);
  • Имя и класс автора;
  • Краткое и полное описание;
  • Жанр и возрастной рейтинг (селекты);
  • Поле выбора файла — <input type="file" accept=".zip">;
  • Кнопка «Отправить на проверку».

Отправка: FormData через fetch POST /api/upload.

Почему ZIP, а не папка

Загрузка папки через <input webkitdirectory> поддерживается не везде и плохо работает на старых браузерах школьных компьютеров. ZIP — универсально, ученику достаточно нажать «Отправить в архив» в файловом менеджере. Инструкция — в gamegenerateprompt.md.

Бэкенд: приём заявки

  1. POST /api/upload принимает ZIP через multer (лимит 15 МБ).
  2. Распаковка adm-zip во временную папку; проверка, что внутри одна корневая папка (сама игра).
  3. Валидация (см. п. 4.8).
  4. Если ошибка — возврат списка проблем, ученик видит их на форме и исправляет.
  5. Если успех — папка переезжает в _pending/<uuid>/, рядом кладётся meta.json с полями из формы, timestamp и IP (для разбора спорных случаев).
  6. Ответ: { ok: true, pendingId, message: "Заявка отправлена преподавателю" }.

Админка преподавателя

Статическая страница admin/index.html (защищена Basic Auth в Nginx):

  • Список заявок из GET /api/pending: обложка, название, автор, описание, дата.
  • Кнопка «Открыть игру» — открывает /api/pending/<id>/preview/index.html в новой вкладке (сервер раздаёт временную папку).
  • Кнопки «Одобрить» (переносит в games/<slug>/) и «Отклонить» (удаляет из _pending/).
  • При одобрении проверяется уникальность slug: если занят, преподаватель может переименовать.

4.8. Валидация (на сервере при приёме заявки)

Реализуется в api/lib/validate.js. Все проверки — блокирующие, при ошибке возвращается 400 со списком проблем.

  1. В ZIP одна корневая папка.
  2. game.json валиден по JSON Schema и содержит все обязательные поля; genre и ageRating — из списков.
  3. slug соответствует ^[a-z0-9][a-z0-9-]{1,40}$; не занят в games/ и в _pending/.
  4. Присутствуют обязательные файлы: index.html, style.css, script.js, game.json, cover.png.
  5. Размер папки игры ≤ 10 МБ; обложка ≤ 500 КБ; разрешение обложки — минимум 256×256.
  6. Разрешённые расширения: .html .css .js .json .png .jpg .jpeg .webp .gif .svg .mp3 .ogg .wav .woff2 .txt .md.
  7. Нет внешних URL в HTML/CSS/JS — regex-скан по https?:// и //cdn. в атрибутах src, href, url(...), а также по fetch(, XMLHttpRequest, navigator.sendBeacon.
  8. Нет абсолютных путей в <script src> и <link href> — только относительные.
  9. Нет eval, new Function, document.write (предупреждение, не блокирует).

4.9. Безопасность

Без CI/CD и без разделения origin'ов модель безопасности строится на трёх принципах:

  1. Модерация — единственный канал публикации. Непроверенный код никогда не попадает в games/. Если в админке Basic Auth, а сервер школьный — риск минимален.
  2. Iframe sandbox при встраивании. Если каталог показывает игру внутри страницы — только через 
    <iframe src="games/snake/index.html"
        sandbox="allow-scripts allow-popups allow-forms"
        referrerpolicy="no-referrer"></iframe>
    Без allow-same-origin: игра не прочитает cookie и localStorage каталога. Если открывать игру в отдельной вкладке — там правила обычные, но это её собственная вкладка, ничего чужого не заденет.
  3. CSP для главной страницы и для игр.
    • Для каталога: script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self'.
    • Для игр: script-src 'self' 'unsafe-inline' (ученикам проще), connect-src 'none' — даже если в игре осталась попытка fetch, браузер заблокирует.

Дополнительно: client_max_body_size 15m в Nginx; ограничение скорости на /api/upload; логирование запросов к /api/upload и /api/pending для разбора инцидентов.

4.10. Настройка сервера (кратко)

  • Ubuntu LTS, пользователь antology, SSH-ключи, UFW (80/443).
  • Nginx: статика из /var/www/game-catalog, reverse-proxy /api/* → 127.0.0.1:3000.
  • Basic Auth для /admin и /api/pending (файл /etc/nginx/.htpasswd, htpasswd -c).
  • Node.js LTS, systemd-юнит antology-api.service, автозапуск при загрузке.
  • Права: games/, _pending/, data/ — на запись пользователю antology; остальное — только чтение.
  • Certbot для TLS (или внутренний CA для LAN).
  • Резервное копирование: games/ и data/ — раз в сутки rsync в отдельную папку/на другой диск.

5.2. Жёсткие правила проекта

Обязательно соблюдать

  • Корень проекта — game-catalog/. Внутри: index.html (главная), games/ (игры), admin/, api/, _pending/, data/.
  • Изоляция игр. Каждая игра — в своей папке games/<slug>/. Никаких общих файлов между играми.
  • Игры самостоятельны. Открытие games/<slug>/index.html напрямую в браузере должно работать без каталога и без сервера.
  • Никакого CI/CD. Никаких GitHub Actions, никаких preview-окружений, никакой сборки.
  • Интерфейс и документация — на русском. Названия игр на главной — из game.json.
  • Голосование: одна сессия = один лайк на игру, тоггл ставить/снимать, счётчик рядом с каждой игрой.
  • Подача игры: кнопка на главной → форма → ZIP → _pending/ → админка → одобрение → games/<slug>/.
  • Модерация — только преподаватель, защищена Basic Auth.
  • Без БД. Только JSON-файлы на диске.
  • Без аутентификации обычных пользователей. Только анонимные сессии для лайков.

5.3. Ограничения (scope)

  • В scope: структура каталога, фронтенд главной и админки, Express-бэкенд (игры, лайки, upload, pending), валидация, конфиг Nginx, документация, демо-игра.
  • Вне scope: разработка самих игр (кроме демо), регистрация/вход пользователей, БД, мобильное приложение, CI/CD.
  • Минимум зависимостей: express, multer, adm-zip, cookie-parser. Всё остальное — встроенное.

5.4. Стиль кода и артефактов

  • Node.js LTS, ESM (или CommonJS — но согласованно по всему проекту).
  • Комментарии на русском, только там, где смысл не очевиден из названий.
  • Документация на русском, в Markdown, с примерами команд.
  • Все секреты (ключ подписи cookie, пароль БД — если появится) — через переменные окружения, никогда в коде.
