# Безопасность

## Модель угроз

Проект предполагает доверенную среду (школьный сервер, ученики и
преподаватели одного заведения). Тем не менее, есть риски:

- Вредоносный JS в игре, отправленной учеником.
- Обход модерации (например, если Basic Auth слабый).
- Нагрузка на сервер (массовые загрузки, лайки).

## Меры

1. **Модерация — единственный путь публикации.** Код в `games/`
   появляется только после approve преподавателя.
2. **Валидатор** отсекает внешние ссылки, `eval`, недопустимые расширения
   и превышение размера.
3. **Rate limit** на лайки — 20 в минуту на сессию.
4. **Nginx** ограничивает размер тела запроса (`client_max_body_size 15m`).
5. **Basic Auth** на `/admin` и `/api/pending`.
6. **Cookie**: `HttpOnly`, `SameSite=Lax`, `Secure` в production.

## Ограничения

- Одна сессия = один лайк. Очистка cookie даёт возможность проголосовать
  повторно — это приемлемо для учебного проекта.
- Пользователи не аутентифицируются, поэтому защиты «один человек — один
  голос» сверх cookie нет.
- Игры на одном origin с каталогом. Если преподаватель одобрил игру с
  вредоносным JS — теоретически он может атаковать каталог. Это ещё один
  аргумент за внимательное ревью.
